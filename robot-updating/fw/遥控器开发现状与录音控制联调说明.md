# StackChan 遥控器开发现状与录音控制联调说明

本文档用于交给新的对话或开发人员，说明当前遥控器已经实现的逻辑，以及“遥控器显示指令已发送，但机器人无法开始、暂停、结束录音”问题的联调重点。

## 2. 遥控器页面顺序

遥控器开机默认进入设置模式，按 A 循环切换：

~~~text
设置模式 → 摇杆运行模式 → IMU 模式 → 会议模式 → 设置模式
~~~

页面编号：

~~~c
MODE_SETUP   = 0
MODE_RUNNING = 1
MODE_IMU     = 2
MODE_MEETING = 3
~~~

主要代码文件：

~~~text
main\StackChan-RemoteControl-ESPNow.cpp
main\ui\ui.c
~~~

按 A 的核心逻辑是：

~~~cpp
uint8_t next_mode = (previous_mode + 1) % 4;
joystick_data.screen_mode = next_mode;
~~~

从设置模式切换到摇杆运行模式时，遥控器会根据当前信道重新初始化 ESP-NOW。

## 3. 遥控器参数

设置页面包含：

- 无线信道：1～13；
- 接收器编号：广播（0）以及 1～50。

当前联调推荐设置：

~~~text
无线信道：1
接收器编号：广播（0）
~~~

也可以设置为：

~~~text
无线信道：1
接收器编号：1
~~~

### 设置方法

1. 在设置模式按 B，在“无线信道”和“接收器编号”之间切换；
2. 黄色背景表示当前正在编辑的项目；
3. 摇杆向上：数值增加；
4. 摇杆向下：数值减少；
5. 按 A 离开设置模式并应用信道。

### 默认值和注意事项

遥控器每次上电时初始化为：

~~~c
channel = 1;
id = 0;
screen_mode = MODE_SETUP;
select_mode = CHANNEL_SELECT;
~~~

当前代码没有把参数保存到 NVS，重新上电后需要重新确认。

机器人会议接收逻辑当前固定：

~~~cpp
constexpr uint8_t kStackChanReceiverId = 1;
~~~

机器人只接受：

~~~text
target_id == 0（广播）
或
target_id == 1（当前机器人编号）
~~~

因此当前不要把接收器编号设置为 2～50。

## 4. 页面按键功能

| 页面 | A 键 | B 键 | 摇杆或 IMU |
|---|---|---|---|
| 设置模式 | 切换到摇杆运行模式 | 切换信道/接收器编号 | 修改当前参数 |
| 摇杆运行模式 | 切换到 IMU 模式 | 切换 btnB_status，保留原有功能 | 控制机器人头部 |
| IMU 模式 | 切换到会议模式 | 切换 btnB_status，保留原有功能 | 通过姿态控制机器人 |
| 会议模式 | 切换回设置模式 | 短按开始/暂停，长按结束 | 当前不参与录音控制 |

摇杆运行模式和 IMU 模式中的 B 键功能仍然保留。机器人原有控制逻辑把 8 字节运动数据包的第 7 字节作为激光开关状态使用。

## 5. 会议模式按键逻辑

主要代码文件：

~~~text
main\StackChan-RemoteControl-ESPNow.cpp
main\joystick\joystick_handle.c
main\ui\ui_meeting_screen.c
~~~

### 短按 B：开始、暂停、继续

B 按下后，如果在 1 秒内释放，遥控器发送：

~~~text
REMOTE_COMMAND_PRIMARY = 1
~~~

机器人端预期状态转换：

~~~text
Idle      → Recording
Recording → Paused
Paused    → Recording
~~~

### 长按 B：结束录音

B 持续按下达到或超过 1000 ms，遥控器发送：

~~~text
REMOTE_COMMAND_END = 2
~~~

机器人端预期：

~~~text
Recording 或 Paused → 保存录音 → Completed
~~~

长按触发结束后，释放 B 不会再次触发短按命令。

### 遥控器页面提示

遥控器只显示本地发送状态：

~~~text
开始/暂停指令已发送
结束指令已发送
~~~

该提示不是机器人返回的确认。当前没有 ACK 或录音状态回传，因此“已发送”不代表机器人已经执行成功。

## 6. ESP-NOW 数据包格式

### 摇杆运行模式和 IMU 模式

原有数据包长度为 8 字节：

| 字节 | 内容 | 说明 |
|---:|---|---|
| [0] | 目标接收器编号 | 0 为广播 |
| [1-2] | yaw | int16_t，小端序，约 -1280～1280 |
| [3-4] | pitch | int16_t，小端序，约 0～900 |
| [5-6] | speed | int16_t，默认 600 |
| [7] | 原有 B/激光状态 | 0 或 1 |

### 会议模式

会议模式发送 9 字节数据包：

| 字节 | 内容 | 当前值 |
|---:|---|---|
| [0] | 目标接收器编号 | 0 或 1 |
| [1-2] | yaw | 0 |
| [3-4] | pitch | 0 |
| [5-6] | speed | 600 |
| [7] | 会议命令 | 1 或 2 |
| [8] | 命令序号 | 每次命令递增 |

命令定义：

~~~c
REMOTE_COMMAND_NONE    = 0;
REMOTE_COMMAND_PRIMARY = 1;
REMOTE_COMMAND_END     = 2;
~~~

每次会议命令会重复发送 5 次，每次间隔约 30 ms：

~~~cpp
joystick_data.remote_command_repeats = 5;
~~~

机器人端应该根据命令序号去重，同一序号只执行一次。

遥控器会议数据包发送代码位于：

~~~text
main\joystick\joystick_handle.c
~~~

## 7. 机器人端预期接收逻辑

机器人接收代码位于：

~~~text
main\hal\hal_espnow.cpp
~~~

收到长度至少 9 字节的数据后，当前协议应按下面方式解析：

~~~cpp
const uint8_t target_id = received_data[0];
const uint8_t command   = received_data[7];
const uint8_t sequence  = received_data[8];
~~~

机器人必须允许：

~~~cpp
(target_id == 0 || target_id == 1)
&&
(command == 1 || command == 2)
~~~

机器人把命令放入队列，会议应用在 onRunning() 中读取：

~~~cpp
while (GetHAL().pollEspNowRemoteCommand(remote_event)) {
    handleRemoteCommand(remote_event.command);
}
~~~

会议应用处理关系：

~~~cpp
MeetingPrimary → handlePrimaryAction();
MeetingEnd     → finalizeMeeting();
~~~

相关代码位于：

~~~text
main\apps\app_meeting\app_meeting.cpp
~~~

## 8. 机器人录音前置条件

机器人会议应用启动时执行：

~~~cpp
GetHAL().startEspNow(1);
~~~

因此会议联调默认要求机器人使用 ESP-NOW 信道 1。

开始录音时，机器人要求 SD 卡已挂载：

~~~cpp
if (!hal_bridge::board_sdcard_is_mounted()) {
    return false;
}
~~~

录音文件保存目录：

~~~text
/sdcard/meetings
~~~

测试前确认：

1. 机器人已经进入 Meeting/会议应用；
2. SD 卡已经插入；
3. SD 卡已经成功挂载；
4. 机器人和遥控器使用同一个信道；
5. 遥控器接收器编号为广播 0 或机器人编号 1。

## 9. 当前已知问题

目前现象：

~~~text
遥控器可以进入会议模式；
短按或长按 B 后，遥控器显示“指令已发送”；
但机器人无法开始、暂停或结束录音。
~~~

目前遥控器端已经具备：

- 会议页面；
- 短按 B 发送命令 1；
- 长按 B 发送命令 2；
- 9 字节会议数据包；
- 命令重复发送；
- 命令序号递增。

所以后续应优先检查机器人端，不要先假定问题仍在遥控器页面。

## 10. 建议排查顺序

### 10.1 确认机器人是否收到 ESP-NOW

查看机器人 COM3 串口日志是否出现：

~~~text
espnow_recv
~~~

如果没有接收日志，检查：

- 遥控器信道是否为 1；
- 机器人实际信道是否为 1；
- 机器人是否已经启动 ESP-NOW；
- 机器人是否先在其他应用中使用了不同信道；
- 遥控器和机器人是否距离过远或初始化失败。

### 10.2 确认数据包长度

会议数据包必须为 9 字节。

确认机器人实际收到：

~~~text
size >= 9
~~~

如果机器人仍然只按 8 字节协议处理，就无法识别会议命令。

### 10.3 确认目标编号

推荐遥控器发送：

~~~text
data[0] = 0
~~~

机器人必须接受：

~~~cpp
target_id == 0 || target_id == 1
~~~

如果机器人端使用了其他固定编号，命令会被丢弃。

### 10.4 确认命令位置

会议模式的命令位置必须是：

~~~text
data[7] = 1：开始/暂停/继续
data[7] = 2：结束
data[8] = 命令序号
~~~

如果机器人把 data[7] 仍然当作激光开关，就不会进入录音控制逻辑。

### 10.5 确认命令队列被读取

确认会议应用持续调用：

~~~cpp
GetHAL().pollEspNowRemoteCommand(remote_event)
~~~

如果命令已进入队列，但会议应用没有轮询，录音状态不会改变。

### 10.6 确认会议命令处理函数

确认以下函数实际被执行：

~~~cpp
AppMeeting::handleRemoteCommand()
AppMeeting::handlePrimaryAction()
AppMeeting::finalizeMeeting()
~~~

### 10.7 确认 SD 卡和录音初始化

如果机器人收到命令但状态进入 Error，检查：

- SD 卡是否挂载；
- /sdcard/meetings 是否可以创建；
- WAV 文件是否可写；
- 麦克风初始化是否成功。

## 11. 机器人端的信道风险

机器人 Hal::startEspNow(int channel) 当前有类似逻辑：

~~~cpp
if (s_espnow_started) {
    return;
}
~~~

这意味着如果机器人已经在其他应用中启动 ESP-NOW，再进入会议应用时，调用 startEspNow(1) 可能不会切换当前信道。

可能出现：

~~~text
遥控器在信道 1；
机器人仍停留在其他信道；
双方无法通信。
~~~

联调时建议：

1. 重启机器人；
2. 直接进入会议应用；
3. 确保会议应用第一次启动 ESP-NOW 时使用信道 1；
4. 遥控器设置为信道 1、接收器编号广播 0。

## 12. 录音测试流程

~~~text
1. 机器人插入 SD 卡并重启；
2. 机器人进入 Meeting/会议应用；
3. 遥控器上电；
4. 设置无线信道 1；
5. 设置接收器编号广播 0；
6. 按 A 进入摇杆运行模式；
7. 再按 A 进入 IMU 模式；
8. 再按 A 进入会议模式；
9. 短按 B，测试开始录音；
10. 短按 B，测试暂停；
11. 短按 B，测试继续；
12. 长按 B 至少 1 秒，测试结束并保存。
~~~

测试时机器人 COM3 串口重点观察：

~~~text
是否收到 espnow_recv；
数据长度是否为 9；
data[0] 是否为 0 或 1；
data[7] 是否为 1 或 2；
data[8] 是否递增；
是否进入 pollEspNowRemoteCommand；
是否调用 handleRemoteCommand；
是否进入 Recording 或 Paused；
是否生成 /sdcard/meetings/*.wav。
~~~

## 13. 当前需要新对话重点回答的问题

请新对话重点检查：

1. 机器人 COM3 当前运行的是否确实是 C:\esp\robot\fw 这套固件；
2. 机器人进入会议应用后实际 ESP-NOW 信道是多少；
3. 机器人是否能看到遥控器发来的 espnow_recv；
4. 收到的数据包长度是否为 9 字节；
5. data[0] 是否为 0 或 1；
6. data[7] 是否被正确解析为 1 或 2；
7. data[8] 的去重逻辑是否错误地丢弃命令；
8. pollEspNowRemoteCommand() 是否在会议应用的运行循环中调用；
9. handleRemoteCommand() 是否实际执行；
10. SD 卡是否挂载并且目录可写；
11. 是否需要增加机器人到遥控器的 ACK 或录音状态回传。

## 14. 当前结论

遥控器端的录音控制协议已经定义为：

~~~text
短按 B：
data[7] = 1
开始/暂停/继续

长按 B：
data[7] = 2
结束并保存
~~~

当前“无法控制录音”优先排查：

~~~text
机器人实际信道；
机器人是否收到 9 字节数据；
目标编号判断；
data[7]/data[8] 解析；
会议命令队列轮询；
会议状态转换；
SD 卡挂载和录音文件创建。
~~~

遥控器显示“指令已发送”只是发送端本地提示，不是执行成功确认。下一步应该通过机器人 COM3 串口日志，逐层确认“收到数据 → 解析命令 → 进入会议应用 → 状态转换 → 创建录音文件”。

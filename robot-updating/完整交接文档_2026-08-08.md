## 2. 我们在做什么

### 2.1 业务背景
公司（金禾天成 / JH）做桌面 AI 机器人，形态参考 StackChan（Cohere 开源），吉祥物为**米宝**（已有完整 PNG 资源库）。老板放桌上使用。

### 2.2 核心使用场景
1. **农业领域 AI 对话**（system prompt 限制为农业专家，`qwen-plus`）
2. **会议录音**（智能会议纪要，自动转写 + 待办提取）
3. **个人记录**（随手语音备忘录，本地存档）
4. **物联网控制**（对接"硅基一号"系统：灯/风扇/水泵/加热垫）

### 2.3 关键约束
- **AI 范围受限**：只答农业问题（规避幻觉与合规）
- **离线可用**：录音本地存档 + 自动同步 web 端
- **品牌差异化**：米宝形象 + 农业领域
- **不做**：dance 移动、Avatar 表情、企业微信、视频推流

### 2.4 技术栈
```
设备端：ESP32-S3 + LVGL 9 + FreeRTOS + xiaozhi-esp32 框架 + mooncake
AI：阿里云百炼（ASR=paraformer / LLM=qwen-plus / TTS=cosyvoice）
后端：FastAPI + Python 3.14 + sqlite（MacBook 本地）
物联网：HTTP POST 到树莓派 Flask（10.51.1.205:5000）
Web 端：Flutter app（实习生交付）
遥控器：M5Stack CardKB（ESP-NOW 协议，29 字节帧）
```

## 3. 总体目标

让米宝一号成为**开箱即用、可靠、可上手的桌面 AI 机器人**，核心体验目标：

1. **可靠配网**：首次开机无 SSID 自动进入配网模式 → 用户手机连热点 → 浏览器配网 → 自动连 WiFi → 进入 launcher。**对标 M5Burner 官方 xiaozhi 固件的配网体验。**
2. **完整功能**：会议录音、个人记录、IoT 控制、文件管理、AI 对话。
3. **二次开机**：有 SSID 直接进 launcher，联网功能正常。
4. **稳定无闪退**：录音、配网、文件管理全流程不崩溃。

## 4. 硬件与软件架构

### 4.1 双框架启动流程
```
app_main()
  → GetHAL().init()
  → 判断 skip_mooncake
      ├─ 无 SSID 或 startAiAgentOnBoot → 【直接 startXiaozhi()】→ xiaozhi 原生配网/AI
      └─ 有 SSID → mooncake 循环（launcher + 各 app）
  → 需要时 startXiaozhi()（永不返回）
```

### 4.2 关键组件关系
| 层 | 说明 |
|---|---|
| **xiaozhi-esp32**（vendored） | `fw/xiaozhi-esp32/`。AI 对话 + **原生 WiFi 配网**（`WifiBoard`） |
| **mooncake** | launcher + 米宝 app（会议/个人/IoT/文件/对话/设置） |
| **board** | `M5StackCoreS3Board` 继承 xiaozhi 的 `WifiBoard` → 原生配网能力 |
| **HAL** | `hal.cpp` / `hal_audio` / `hal_mcp` / `hal_espnow` / `hal_network` 等 |

**关键结论**：xiaozhi 原生配网（`WifiBoard::StartNetwork`）**已内置**，与 M5Burner 官方固件同源。问题在于 mooncake launcher 阶段曾用自定义 worker 接管配网导致闪退。

## 7. 当前堵塞点（最重要）

### 7.1 ★配网功能未解决
- **现象**：手机配网页显示"配置成功"，随后设备立即闪退/重启。
- **已尝试 6 轮方案**（均未根治）：
  1. 原生引导（StartupWorker，需手机 App）→ 弃用
  2. 自定义 HotspotSetupWorker（mooncake 阶段）→ 配网后闪退
  3. StartStation 移出 LVGL 线程 → 仍闪退
  4. StartConfigAp/StopConfigAp 移独立任务 → 仍闪退
  5. submit 保存后主动 `esp_restart()` → 仍"闪退"
  6. **（当前）xiaozhi 原生配网移植**：无 SSID 时 `skip_mooncake` 直接进 xiaozhi 配网，配网成功 `WifiBoard` 检测 `provisioned_this_session_` 后主动重启回 launcher → **用户最新反馈"还是不行"**
- **最大障碍**：**至今未拿到串口日志**，无法区分是 panic 崩溃还是主动/意外重启，无法定位行号。

### 7.2 mooncake 与 xiaozhi 双框架配网节奏冲突（疑点）
- 两套配网逻辑（cimen 阶段自定义 worker + xiaozhi 原生）可能互相干扰。
- 排查 `hal_espnow.cpp` 是否重复初始化 esp_wifi。

### 7.3 M5Burner 官方固件可配网但无法反编译
- 官方 `StackChan-MCP` / `xiaozhi v2.6.6` 配网正常（用户实测），但 `.bin` 无法直接改造成我们的 launcher 形态。
- 有参考价值的是**官方源码**：`/Users/cobain/Documents/stackchan-mcp-analysis/`。

## 11. 下一步建议（按优先级）

1. **【最高】抓串口日志，定位配网闪退根因**（见 8.4）。区分 panic vs 主动重启。
2. **确认当前 xiaozhi 原生配网是否真实生效**：烧录后开机应**直接进配网**（屏幕显示热点提示），而非 launcher。若仍进 launcher，说明 `skip_mooncake` 的 SSID 判断 / NVS 未按预期（`erase` 未真正清 NVS，或 `SsidManager` 空判断有误）。
3. **对比验证**：用 M5Burner 烧官方固件确认本硬件配网正常，再对照 `stackchan-mcp-analysis` 逐行核对。
4. **排查 ESP-NOW 冲突**：`hal_espnow.cpp` 是否与配网重复初始化 esp_wifi。
5. 配网稳定后，继续阶段 2~5（唤醒词、三大功能、Web 对接、AI 农业对话）。

## 1. 项目概况

- **产品**：米宝一号（Stackstan），基于 M5Stack StackChan（CoreS3，ESP32-S3，320×240 IPS 触摸屏）的桌面机器人，二次开发自 xiaozhi-esp32 v1.4.3 开源框架。
- **功能定位**：AI 对话（农业专家）、会议录音转纪要、个人灵感记录、温室物联网控制（硅基一号树莓派 Flask）、屏保陪伴。
- **端云分工**（产品定义文档 §2.1）：设备端负责录音/Wi-Fi/HTTP；电脑后端 FastAPI 负责录音接收、百炼 ASR/LLM/TTS、Web 管理、IoT 网关。

### 3.2 烧录规范（HANDOVER.md §8.3）

- 串口：`/dev/cu.usbmodem1301`（ESP32-S3 USB-Serial/JTAG，MAC 68:ee:8f:d7:3b:68）
- 下载模式：**长按底部 RST 约 3 秒**（绿灯亮）；短按 RST = 普通复位
- 顺序：先 `erase_flash`，再写 5 个分区：

| 地址 | 文件 |
|---|---|
| 0x0 | bootloader/bootloader.bin |
| 0x8000 | partition_table/partition-table.bin |
| 0xd000 | ota_data_initial.bin |
| 0x20000 | stack-chan.bin |
| 0xA00000 | generated_assets.bin |

- 参数：`--flash_mode dio --flash_size 16MB --flash_freq 80m`
- 产物位于 `/Users/cobain/robot-build/fw/build/`
- 注意：USB-Serial-JTAG 无 RTS 线，工具无法远程复位设备；烧录后需用户短按 RST 启动

### 3.3 日志控制台（重要，本交接时点状态）

- **当前烧录在设备上的固件日志控制台在 USB-Serial-JTAG**（sdkconfig.defaults 已加 `CONFIG_ESP_CONSOLE_USB_SERIAL_JTAG=y`），用 pyserial 115200 监听 `/dev/cu.usbmodem1301` 即可抓日志（已验证可行，见 serial_log.txt）。
- 若要恢复 UART0 为控制台，删除 sdkconfig.defaults 中该行并删镜像 sdkconfig 后 reconfigure 重建。
- 抓日志工具示例：`python3 -m serial.tools.miniterm /dev/cu.usbmodem1301 115200`

## 5. 未解决问题（2026-08-08 更新：三大问题已全部解决）

### 5.0 配网问题最终根因与修复（2026-08-08 闭环，务必理解以保证稳定）

**现象**：手机提交 Wi-Fi 密码后设备必现 abort 重启（原生 xiaozhi 配网与 Hotspot Setup 两条路径都崩）。

**根因（两层）**：
1. **底层时序 bug（最终根因）**：`managed_components/78__esp-wifi-connect/wifi_station.cc::Start()` 在 `esp_wifi_start()` **之前**调用 `esp_wifi_set_band_mode()`，驱动处于停止态返回 `ESP_ERR_WIFI_NOT_STARTED(0x3002)`，被 `ESP_ERROR_CHECK` 放大为 abort。同组件 `wifi_configuration_ap.cc` 里同样的调用放在 start 之后是正确的——两处代码不一致，一处埋雷。修复：把调用移到 `esp_wifi_start()` 之后，并把错误检查降级为警告（ESP32-S3 只有 2.4G，该调用非关键）。此修复同时治好了两条配网路径（它们共用 WifiStation::Start）。
2. **上层时序 bug（叠加）**：HotspotSetupWorker 曾在配网退出事件的同步通知链里立即调 StartStation（此时驱动刚 stop）。修复：事件回调零捕获只置原子标志，StartStation 延迟 2 秒在轮询侧/独立任务执行。

**稳定性保证**：托管组件的 patch 已加注释标记；日后若更新 esp-wifi-connect 组件，必须复查 band_mode 调用时序。铁律：**Wi-Fi 驱动 stop/start 切换的通知链中禁止同步执行依赖驱动就绪的操作**。

**物联网点击重启**也已随配网链路修复验证通过（2026-08-08 用户真机确认）。

## 7. 关键技术约定与铁律（违反必出事故）

1. **日志**：用 `mclog::tagInfo/tagError`，不用 ESP_LOGI。
2. **字体 fallback**：严禁 `const_cast` 修改 lv_font_conv 生成的 const 字体（flash 只读段，写了必 panic）；必须 RAM 副本 memcpy 后挂 fallback。
3. **LVGL 回调**：禁止在回调内做 HTTP/cJSON/fmt 等深栈操作；卸载到 ≥8KB 独立 FreeRTOS 任务，UI 侧原子标志轮询。
4. **SD 访问**：一切 SD 读写包在 `SdCardAccessGuard` 内（GPIO35 与 LVGL 复用，需停 LVGL、切 GPIO 路由）。
5. **录音**：FreeRTOS 主动轮询 codec 取数（禁止被动 onMicData 回调）；WAV 占位头结束后回填。
6. **配置**：NVS 命名空间 `mibao`（upload_url / iot_url / ai_chat_enabled）；xiaozhi 的 `ota_url` 在 NVS `wifi` 命名空间。
7. **资源**：assets 分区已用 5.51M/5.94M（余约 700KB），字体走 app 分区（C 字体进代码段）；不覆盖原生 icon 资源名。
8. **构建**：改 CMakeLists/新增源文件必须 reconfigure；全量重建用 `./scripts/build.sh full`。
9. **中文字体生成**：`npx lv_font_conv`，命令模板在 `fw/main/assets/fonts/mibao_zh_font.c` 文件头；新增文案先核对字符是否在子集内，缺字则重新生成。

## 8. xiaozhi 协议对接要点（S5 备用）

- OTA 激活：设备 POST `NVS wifi/ota_url`（空则回退官方云），带 Device-Id/Client-Id 头；响应含 `websocket{url,token}` 或 `mqtt{...}` 段决定通道。
- WebSocket：hello 握手（version 3、opus 16kHz、60ms 帧）→ 上行 `listen` 状态 JSON + 二进制 opus 帧 → 下行 `tts/stt/llm/mcp/system` JSON + opus 音频。
- `mcp` 下行 JSON-RPC 是语音控制温室设备的入口（设备端 McpServer 已就绪）。
- 建议直接 fork 开源 xiaozhi-esp32-server（Python/FastAPI）替换百炼 provider，勿从零实现（约省 5-7 人天）。注意 cosyvoice-v2 输出 22050Hz mp3 需转 16k opus 回传；paraformer 需裸 PCM（去 WAV 头）。

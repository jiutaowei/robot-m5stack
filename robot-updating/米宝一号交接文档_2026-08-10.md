## 2. 项目概况

### 2.1 业务背景
金禾天成（JH）桌面 AI 机器人，形态参考 StackChan（Cohere 开源），吉祥物 **米宝**。老板放桌上使用。

### 2.2 核心使用场景
1. **农业领域 AI 对话**（system prompt 限制为农业专家，`qwen-plus`）
2. **会议录音** → 自动转写 + 纪要总结（百炼 paraformer + qwen）
3. **个人灵感记录**（语音备忘录，本地存档 + 可同步 Web）
4. **物联网控制**（对接"硅基一号"温室系统：灯/风扇/水泵/加热垫）

### 2.3 技术栈
```
设备端：  ESP32-S3 + LVGL 9.4 + FreeRTOS + xiaozhi-esp32 + mooncake
AI：     阿里云百炼（ASR=paraformer-realtime-v2 / LLM=qwen-plus / TTS=cosyvoice-v2）
后端：   FastAPI + Python 3.14 + sqlite（MacBook 本地）
Web 管理：原生 HTML/JS（无前端构建链，单页 4 Tab）
物联网：  HTTP POST 到树莓派 Flask（10.51.1.205:5000）
```

## 6. 固件核心逻辑

### 6.1 启动流程（`main.cpp`）

```
app_main()
  → GetHAL().init()
  → 判断 skip_mooncake（仅当 startAiAgentOnBoot 且非 warm reboot 时跳过）
      ├─ 跳过 → 直接 startXiaozhi()（永不返回）
      └─ 不跳过 → mooncake 循环（加载全部米宝 app）
          ├─ AppLauncher：无 SSID → 自动 HotspotSetupWorker 配网
          │                有 SSID → 创建 launcher 视图 + 后台配置拉取任务
          ├─ AppSetup / AppMeeting / AppChat / AppMibaoPersonal
          ├─ AppMibaoIot / AppMibaoFiles
          └─ 需要时 break → startXiaozhi()
```

**关键修复（门控死局）**：`skip_mooncake` 仅由 `startAiAgentOnBoot` 控制，不再因 `no_saved_ssid` 跳过 mooncake。无 SSID 时 launcher 自动创建 `HotspotSetupWorker` 进入配网，保证"门控只优化体验、绝不切断最后的配网入口"。

### 6.2 配网流程

```
开机 → launcher::onLauncherOpen()
  → SsidManager 检查无保存 SSID
  → 自动创建 HotspotSetupWorker（独立高栈 FreeRTOS 任务）
  → 启动 SoftAP（xiaozhi_xxxx 热点）
  → 手机连接热点 → 浏览器 192.168.4.1
  → 选择 Wi-Fi → 输入密码 → 提交
  → 保存凭证 → 关闭 AP → 纯 STA 连接
  → 连接成功 → 自动回到 launcher
```

**配网修复历史**（2026-08-08 闭环）：
- 根因：`esp_wifi_set_band_mode()` 在 `esp_wifi_start()` 之前调用 → `ESP_ERR_WIFI_NOT_STARTED` → abort
- 修复：调用移到 `esp_wifi_start()` 之后，错误检查降级为警告
- 稳定性保证：Wi-Fi 驱动 stop/start 切换的通知链中禁止同步执行依赖驱动就绪的操作

### 6.3 设备配置自动拉取

```
launcher 启动（有 SSID 且 upload_url 非空时）
  → 创建独立 FreeRTOS 任务 config_pull（8KB 栈）
  → HTTP GET {upload_url origin}/api/device/config
  → 解析 JSON，更新 NVS（upload_url / iot_url / ota_url）
  → 无论成败只尝试一次，不阻塞 UI
```

**NVS 命名空间**：`mibao`，键名：
- `upload_url`：录音文件上传地址
- `iot_url`：IoT 控制服务基础地址（默认 `http://10.51.1.205:5000`）
- `ota_url`：OTA 升级服务器地址
- `ai_chat`：是否允许对话入口进入 xiaozhi（默认 false）
- `auto_prov`：是否允许开机自动配网（默认 false）

## 8. AI 对话服务（xiaozhi-server）

### 8.1 概述

fork 自 [xinnan-tech/xiaozhi-esp32-server](https://github.com/xinnan-tech/xiaozhi-esp32-server)，为米宝一号提供 xiaozhi 协议服务端。

### 8.2 启动命令

```bash
cd xiaozhi-server
bash scripts/install_deps.sh        # 首次：Python 3.10 venv + 依赖
source .venv/bin/activate
python app.py                       # 启动：WebSocket 8001，HTTP(OTA) 8003
```

> **注意**：必须用 **Python 3.10**（本机 `/opt/homebrew/opt/python@3.10`），依赖锁了 torch==2.2.2 等旧版本。

### 8.3 百炼三件套配置

| 环节 | provider | 模型 | 说明 |
|---|---|---|---|
| ASR | `aliyunbl_stream` | paraformer-realtime-v2 | WebSocket 流式，16k PCM |
| LLM | `openai` | qwen-plus | 百炼 OpenAI 兼容端点 |
| TTS | `alibl_stream` | cosyvoice-v2 | WebSocket 流式，输出 PCM 转 opus |

**密钥生成**（API Key 在 `04_API KEY/默认业务空间-apiKey-6466462.xlsx`）：
```bash
python scripts/extract_key_and_gen_config.py \
  "/path/to/04_API KEY/默认业务空间-apiKey-6466462.xlsx" \
  data/.config.yaml
```

**当前状态**：`data/.config.yaml` **已生成**（2026-08-08，~1.7KB），三件套凭据已验证有效：`verify_bailian.py` 实测 **LLM=OK / ASR=OK / TTS=OK**（注意：该脚本 ASR/TTS 需带 `Authorization: Bearer` 鉴权头，已修复；`device_handshake_test.py` 需用 `additional_headers=` 而非已废弃的 `extra_headers=`，已修复）。

### 8.4 设备对接

设备端 `ota_url` 设为：
```
http://<电脑IP>:8003/xiaozhi/ota/
```

设备 POST OTA 后，服务端返回 `websocket.url`，设备据此建立 WebSocket 通道。

## 11. 关键设计决策与铁律

### 11.1 架构决策

| # | 决策 | 选择 | 理由 |
|---|---|---|---|
| 1 | 配网方案 | **xiaozhi 原生配网 + launcher 兜底** | 复用官方，已验证稳定 |
| 2 | 配置管理 | **统一 Web 后台 + 设备端自动拉取** | 避免小屏幕操作，集中管理 |
| 3 | 录音上传 | **默认不上传，本地存档** | 用户可控，后续可手动配置 |
| 4 | IoT 协议 | **HTTP（hal_mcp.cpp）** | 树莓派 Flask 现有接口 |
| 5 | 唤醒后 | **直接进 AI 对话** | 不停 launcher，体验流畅 |
| 6 | 编译路径 | **镜像目录 `/Users/cobain/robot-build/fw/`** | 避免方括号路径 CMake 错误 |

### 11.2 铁律（违反必出事故）

1. **日志**：用 `mclog::tagInfo/tagError`，不用 `ESP_LOGI`。
2. **字体 fallback**：严禁 `const_cast` 修改 lv_font_conv 生成的 const 字体（flash 只读段，写了必 panic）。
3. **LVGL 回调**：禁止在回调内做 HTTP/cJSON/fmt 等深栈操作；卸载到 ≥8KB 独立 FreeRTOS 任务。
4. **SD 访问**：一切 SD 读写包在 `SdCardAccessGuard` 内（GPIO35 与 LVGL 复用）。
5. **录音**：FreeRTOS 主动轮询 codec 取数（禁止被动 onMicData 回调）。
6. **配置**：NVS 命名空间 `mibao`，xiaozhi 的配置在 NVS `wifi` 命名空间。
7. **资源**：assets 分区已用 5.3M/5.94M（余约 600KB），字体走 app 分区（C 字体进代码段）。
8. **构建**：改 CMakeLists/新增源文件必须 reconfigure；全量重建用 `./scripts/build.sh full`。
9. **中文字体**：新增文案先核对字符是否在子集内，缺字则重新生成。
10. **Wi-Fi 驱动**：stop/start 切换的通知链中禁止同步执行依赖驱动就绪的操作。

## 13. 警告与注意事项（置底）

- **不要在 Trae 内置终端跑 build/usb 操作**（沙盒限制）→ 用 macOS Terminal.app
- **不要用含方括号的路径直接 build** → 必须用 `/Users/cobain/robot-build/fw/` 镜像
- **烧录前尽量 `erase_flash`**，bootloader offset 必须 0x0
- **改 CMakeLists 后必须 fullclean**（`./scripts/build.sh full`）
- **修改 `managed_components/` 或 `xiaozhi-esp32/` 会同时影响 xiaozhi 正常逻辑**，先评估影响面
- **不要**用 `onMicData` 被动回调录音 → 必须 FreeRTOS task 主动轮询 codec
- **不要**用 220×220 屏保图 → 统一 ≤150×150
- **不要**覆盖原生 app 图标 → 用新名字 `mibao_xxx.bin`
- **中文乱码** → 需重新生成字体子集（`meeting_zh_font.c` / `mibao_zh_font.c`）
- **API Key 严禁入库/入 git/出现在日志或报告中** → 对外展示一律用 `sk-***` 掩码
- **xiaozhi-server 必须用 Python 3.10**，Python 3.14 无对应 wheel
- **编译产物** `/Users/cobain/robot-build/fw/build/stack-chan.bin` 4.0MB 已就绪（2026-08-09 17:16），可直接烧录
- **镜像目录占用空间** `/Users/cobain/robot-build/` 约 **1.4GB**（含 build 产物 + components）

## 1. 产品定义

### 1.1 基本信息
- **产品名**：米宝一号（Mibao One）
- **设备 ID**：`mibao-01`
- **形态**：StackChan 桌面机器人（基于 CoreS3 / ESP32-S3，240×240 触摸屏，1.4" AMOLED）
- **公司品牌**：金禾天成 / JH
- **吉祥物**：米宝（已有完整 PNG 资源库：看你_睁眼、看你_闭眼、认真工作、米宝_开会、米宝_物联网、米宝_对话、米宝_个人灵感）
- **目标用户**：老板的桌面工作助手
- **核心场景**：
  1. 农业行业 AI 对话（限制领域）
  2. 智能会议纪要（录音 + ASR + LLM 总结 + 待办提取）
  3. 个人记录（随手语音备忘录）
  4. 物联网控制（对接"硅基一号"，灯/风扇/阀门/补光灯）

### 1.2 核心功能需求（用户明确确认）

| 功能 | 描述 | 实现位置 |

## 3. 优化方向（按用户反馈）

### 3.1 当前完成度问题（用户已确认）

| 编号 | 问题 | 根因 | 修复方案 |

| P1 | 屏保显示变色方块+MIBAO-01 | bin 文件 cf 字段错（ARGB8888 但实际像素 RGB888） | 用 PIL + LVGLImageFormatter 重新生成 150×150 ARGB8888 bin |
| P2 | 4 个新应用图标非定制 | 脚本借用现有 icon | 调用 seedream 生成米宝主题图标，转 bin |

### 3.2 整体方案（用户已批准）

**方案 A：固件层 + 后端 + Web 端 全栈**

1. **固件层（米宝 HAL + App）**
   - 屏保：自定义 LVGL，米宝睁/闭眼图片循环
   - 4 个 app：meeting / personal / iot / settings
   - 录音：FreeRTOS task 主动轮询 codec
   - 唤醒：ESP-SR MultiNet 自定义命令词
   - 通信：HTTP/WS 对接后端
   - 物联网：HTTP POST 到后端网关

2. **后端层（FastAPI）**
   - 录音接收 + 标签
   - 阿里百炼 ASR/LLM/TTS
   - 物联网设备控制网关（转发到硅基一号）
   - Web 管理端 API

3. **Web 端（可选）**
   - 录音文件管理（按 type 筛选）
   - 转写结果查看
   - 会议纪要总结
   - 待办事项
   - ASR/LLM/TTS 配置框

### 3.3 唤醒词方案（2026-08-10 更新决策）

**当前决策：先用 xiaozhi-server 已配置的"你好，米宝"跑通 AI 对话链路（优先级最高）；MultiNet6 自定义命令词"米宝米宝"（原 C 方案）暂缓至阶段 6，待对话通路打通后再切换。**

原方案对比存档：

| 方案 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| A | 不动 xiaozhi 框架 | 简单 | 只能用英文唤醒词 |
| B | 改默认 WakeNet 为中文 | 简单 | 中文模型识别率低 |
| C（暂缓） | 替换 MultiNet 命令词列表为"米宝米宝" | 支持自定义中文命令词 | 需要打包 multinet6_zh.bin，且依赖对话链路先打通 |

**C 方案实施步骤**：
1. 复制 `esp-sr/model/multinet6_zh.bin` 到固件 `model/` 目录
2. 修改 `xiaozhi-esp32/main/audio/wake_words/afe_wake_word.cc`：
   - 命令词列表改为 `["mi bao mi bao"]`
   - 替换 `esp-sr` 里的 multinet 模型
3. 触发后回调 `application.cc` 的事件分发 → 启动 AI 对话 + 显示小图 + 文字

## 4. 跨项目经验（参考智能手表小智方案）

### 4.1 录音功能

| 项目 | 录音方案 |
|------|---------|
| 智能手表 [voice_recorder](file:///Users/cobain/Documents/Arduino/voice_recorder) | `loop()` 中 `i2s_read() + file.write()` |
| StackChan | FreeRTOS task + `codec->Read(buf, n) + onMicData(buf, n)` |

**核心要点**：
- 必须是**主动轮询** task，不是被动回调
- 启动时 `codec->EnableInput(true)`
- 停止时 `task 退出 + codec->EnableInput(false)`
- WAV 头：开始占位，结束回填 `data_size`
- 文件名：`rec_YYYYMMDD_HHMMSS.wav`
- 5 分钟自动切分段

### 4.2 UI 模式
- 顶部状态 label（时间/Wi-Fi/电量）
- 中部时间 label（青色大字体）
- 中部大按钮（红色"开始录音"）
- 底部上传按钮 + 警告 label

### 7.4 唤醒词方案（2026-08-10 更新：暂缓）

> **当前用 xiaozhi-server 配置的"你好，米宝"。以下 C 方案（自定义"米宝米宝"）存档备用，待 AI 对话链路打通后启动。**

#### 7.4.1 改 Kconfig 启用 MultiNet6

**修改 `firmware/sdkconfig.defaults`**：
```diff
-CONFIG_LANGUAGE_EN_US=y
+CONFIG_LANGUAGE_ZH_CN=y
-CONFIG_SR_WN_WN9_HISTACKCHAN_TTS3=y
+# CONFIG_SR_WN_WN9_HISTACKCHAN_TTS3 is not set
 USE_CUSTOM_WAKE_WORD=y
+CONFIG_CUSTOM_WAKE_WORD="mi bao mi bao"
+CONFIG_CUSTOM_WAKE_WORD_DISPLAY="米宝"
+CONFIG_SR_MN_CN_MULTINET6_QUANT=y
```

#### 7.4.2 米宝 HAL Hook 唤醒回调

**策略**：不动 xiaozhi application.cc，**Board State 轮询** + 后续可选直接 hook。
- 米宝 launcher 每 200ms 读 `Board::GetInstance().GetDeviceState()`
- idle → listening 转变时，overlay 米宝小图 + 文字"我在" + 3 个功能引导
- 状态恢复 idle 时，移除 overlay
- 后续如需更精准可在 `application.cc::HandleWakeWordDetectedEvent` 加 #ifdef MIBAO_BUILD 调用

**为什么不动 xiaozhi**：保留框架升级兼容性，200ms 轮询用户感知不到延迟。

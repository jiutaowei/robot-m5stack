# StackChan 生态资源与方案选型(AI 对话助手 + 会议纪要)

> 面向本项目两个目标功能:**① 农业行业 AI 对话助手 ② 智能会议纪要**
> 调研时间:2026-07-02 | 方式:联网搜索 + GitHub/官方文档抓取

---

## 一、方案选型结论(先看这里)

| 目标功能 | 推荐技术底座 | 理由 |
|---------|------------|------|
| 农业 AI 对话助手 | **xiaozhi-esp32** | 官方支持 CoreS3、流式 ASR+LLM+TTS、中文、ESP-SR 离线唤醒、MIT 可商用、社区活跃 |
| 智能会议纪要 | **xiaozhi-esp32 改造 + 服务端转写** | 复用其 OPUS 录音/SD 存储 能力,上传服务端调讯飞/阿里 ASR + LLM 摘要 |

> ⚠️ 重要纠正:之前 MIC 示例中"麦克风和扬声器不能同时使用"是 **M5Unified 库的软件限制,非 CoreS3 硬件限制**。CoreS3 的 ES7210(双麦)+ AW88298(功放)是独立芯片 + 双 I2S 总线,**硬件支持全双工**。xiaozhi-esp32 用 ESP-IDF 原生 I2S 驱动已实现流式双工,并可用 ES7210 的 AEC 做回声消除。

## 四、语音能力(ASR / TTS)

### 4.1 端侧(ESP32-S3 本地)
| 方案 | 类型 | 中文 | 说明 |
|------|------|------|------|
| **ESP-SR**(乐鑫官方) | 唤醒词 WakeNet + 命令词 MultiNet | ✅ | xiaozhi-esp32 即用此做离线唤醒;github.com/espressif/esp-sr |
| ESP-Skainet | 语音交互框架 | ✅ | 集成 WakeNet/MultiNet/AFE |
| 端侧完整 ASR | ❌ 不现实 | — | ESP32-S3 算力不足以跑 Whisper 级中文连续识别,仅适合唤醒词/短命令 |

### 4.2 云端 ASR(STT)
| 方案 | 中文 | 接入 |
|------|------|------|
| OpenAI Whisper API | ✅ | REST |
| Google Cloud STT | ✅ | REST/gRPC |
| 火山引擎 Doubao-Seed-ASR-2.0 | ✅ 优 | REST,上下文召回 +20% |
| 百度/讯飞/阿里云语音 | ✅ 优 | 成熟 REST API,中文方言好 |

### 4.3 云端 TTS(中文可用,优于 VOICEVOX)
| 方案 | 中文 | 特点 |
|------|------|------|
| **edge-tts**(微软免费) | ✅ 优 | 免费、多中文音色、低延迟,可自建代理 |
| **CosyVoice**(阿里开源) | ✅ 优 | 3秒克隆、97ms延迟、300M精简版可本地 |
| OpenAI TTS | ✅ | 简单稳定 |
| ElevenLabs | ⚠️ 中文一般 | stack-chan 官方已支持,付费 |
| VOICEVOX | ❌ 日文 | AI_StackChan2 用,不适合中文 |
| 百度/讯飞 TTS | ✅ 优 | 成熟 |

### 4.4 全双工实现路径(重要)
CoreS3 硬件支持全双工,业界实现路径:
1. **AEC 回声消除**(ES7210 已支持)
2. **软件 VAD 端点检测**
3. **流式 ASR**(边说边识别)
- xiaozhi-esp32 已走通流式架构,建议直接采用。

## 五、智能会议纪要方案

### 5.1 StackChan 录音能力评估
| 维度 | CoreS3 实况 | 评估 |
|------|-----------|------|
| 麦克风 | ES7210 双麦,24-bit | ✅ 满足会议录音 |
| 存储 | microSD(SPI:CS=4/SCK=36/MISO=35/MOSI=37) | ✅ 16GB 可录十余小时 |
| 上传 | WiFi 2.4G | ✅ 带宽足够 |
| 算力 | ESP32-S3 + 8MB PSRAM | ✅ 可本地录 OPUS 并分片上传 |
| 远场拾音 | 桌面级双麦 | ⚠️ 大会议室远场有限,适合桌面/小型会议 |

### 5.2 转写 API 选型
| 服务 | 中文 | API | 备注 |
|------|------|-----|------|
| **讯飞开放平台** | ✅ 最优 | REST | 中文方言最强,有开发者 API |
| 通义听悟(阿里) | ✅ 优 | REST | 阿里云语音转写 API |
| 火山引擎 Doubao-ASR | ✅ 优 | REST | 适合与豆包 LLM 串联 |
| OpenAI Whisper | ✅ | REST | 多语言,中文方言弱 |
| 飞书妙记 | ✅ 优 | ❌ 无公开上传 API | 适合飞书生态内人工上传 |

### 5.3 实现路径
```
StackChan 录音(OPUS→SD卡)
    ↓ HTTP 分片上传
服务端(自建)
    ↓ 调 ASR API(讯飞/阿里)
转写文本
    ↓ 调 LLM(DeepSeek/Qwen)
摘要 + 待办 + 发言人区分
    ↓
会议纪要输出
```
> 未找到专门针对 ESP32 的端到端会议纪要开源项目,需自行拼装。xiaozhi-esp32 的流式 ASR 架构可改造为"持续推流"的实时会议转写模式。

## 七、风险提示

1. **VOICEVOX 不支持中文**:AI_StackChan2 默认 TTS 无法用于中文,必须替换。
2. **stack-chan 官方固件活跃度低**:2022 年最后发布,JS/Moddable 技术栈小众,中文资源少。
3. **飞书妙记无公开上传 API**:自动化纪要优先选讯飞/阿里/火山等有 REST API 的服务。
4. **农业知识库需自建 RAG**:无现成可商用数据集。
5. **会议远场拾音局限**:CoreS3 双麦为桌面级,定位"桌面/小型会议纪要"更现实;大会议室建议外接 USB 麦克风阵(CoreS3 支持 OTG)。
